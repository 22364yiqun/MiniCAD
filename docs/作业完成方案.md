# 第一次作业完成方案：直线操作的 Undo/Redo

## 1. 先确定作业范围

根据 `readme.md`，本次作业的最低必做范围是：

- 参考 QCAD 的 `Cmd`/`Entity` 类设计；
- 以直线实体为对象，实现创建、删除、移动、旋转、镜像；
- 实现 Undo 和 Redo；
- 正确维护实体操作数、系统操作数（如果采用操作数方案）；
- 正确释放历史记录和实体占用的内存。

作业 PPT 中还列出了文件、填充、尺寸标注、特殊符号、函数曲线、标准件和图形块等扩展方向。这些不是 `readme.md` 当前明确要求的最低内容，除非老师另有通知，不建议先投入这些功能。

## 2. 推荐的总体实现方式

建议沿用课件中的命令模式：

```text
用户鼠标/菜单操作
        |
        v
具体命令 Cmd（CreateLineCmd、MoveLineCmd 等）
        |
        v
直线实体 Entity（保存端点、显示和几何变换）
        |
        v
实体容器 + Undo/Redo 历史管理器
```

每个用户操作都封装成一个命令对象。执行命令时修改模型并进入 Undo 栈；撤销时调用命令的 `undo()`；重做时调用 `redo()` 或重新执行命令。这样可以把交互代码和历史管理分开，也符合 VCAD/QCAD 课件中的 `CCommand`/`CEntity` 思路。

如果老师提供的框架已经有 `MCommand`、`MEntity`、实体链表或命令队列，应优先继承和扩展现有类，不要另起一套互不兼容的模型。

## 3. 直线实体设计

直线至少需要保存以下数据：

```text
LineEntity
  id                 唯一标识
  start, end         两个端点（世界坐标）
  visible/deleted    当前是否显示或已删除
  entityOp           实体版本/操作数（采用操作数方案时使用）
```

实体应提供以下基础接口：

```text
draw()
clone()
move(dx, dy)
rotate(center, angle)
mirror(axis)
markDeleted()
restore()
```

几何计算应使用世界坐标，显示时再通过视窗的坐标变换映射到屏幕坐标。这样缩放和平移不会改变模型数据。

## 4. 五类必做操作

### 4.1 创建

1. 鼠标第一次点击得到起点；
2. 鼠标移动时显示橡皮筋直线；
3. 第二次点击得到终点并创建 `LineEntity`；
4. 将“创建”命令压入 Undo 栈；
5. 清空 Redo 栈。

Undo 创建操作时删除或隐藏该实体；Redo 时恢复或重新创建该实体。

### 4.2 删除

1. 进入选择状态并拾取直线；
2. 保存删除前的实体状态；
3. 执行删除，推荐先标记删除而不是立即释放；
4. 将删除命令加入 Undo 栈。

Undo 时恢复实体和其原位置；Redo 时再次标记删除。只有确认历史记录不再需要该实体时，才能真正释放内存。

### 4.3 移动

保存移动前后的端点：

```text
oldStart, oldEnd
newStart = oldStart + (dx, dy)
newEnd   = oldEnd   + (dx, dy)
```

Undo 恢复 `oldStart/oldEnd`，Redo 设置为 `newStart/newEnd`。交互过程中用橡皮筋或临时预览显示目标位置，确认后才生成一条历史记录，避免鼠标移动的每一帧都进入 Undo 栈。

### 4.4 旋转

围绕指定中心点 `C(cx, cy)` 旋转角度 `θ`。任意端点 `P(x,y)` 的旋转公式为：

```text
x' = cx + (x-cx)cosθ - (y-cy)sinθ
y' = cy + (x-cx)sinθ + (y-cy)cosθ
```

保存旋转前后的两个端点以及旋转中心和角度。Undo 应使用保存的旧坐标，而不是通过角度近似反算，以减少浮点误差。

### 4.5 镜像

明确镜像轴的定义，例如水平轴、垂直轴或由两点确定的任意直线。对端点分别进行镜像，保存操作前后的坐标。对任意镜像直线，设轴上一点为 `A`，单位方向向量为 `u`，点 `P` 关于轴的镜像可按“投影点的两倍减去原点”计算：

```text
Q = A + u * dot(P-A, u)
P' = 2Q - P
```

Undo/Redo 仍然直接恢复旧坐标或新坐标，不重复计算。

## 5. Undo/Redo 的两种实现方案

### 方案 A：命令对象保存前后状态（推荐起步）

每个命令保存：

```text
commandType
entityId
beforeState
afterState
```

Undo 栈保存已经执行的命令，Redo 栈保存已经撤销的命令：

```text
执行新命令：execute -> undoStack.push -> redoStack.clear
Undo：undoStack.pop -> command.undo -> redoStack.push
Redo：redoStack.pop -> command.redo -> undoStack.push
```

优点是实现直观、调试简单、每个操作的行为清楚。缺点是需要妥善保存创建和删除操作涉及的实体生命周期。

### 方案 B：操作数 + 双十字链表（作业中标注的可选方案）

该方案需要同时维护：

- **系统操作数**：当前全局历史位置；
- **实体操作数**：某条直线最后一次有效修改所在的历史位置；
- **实体链表**：同一实体的多个历史版本；
- **系统链表**：不同操作之间的先后关系。

显示规则可以采用课件中的原则：对每个实体，只显示“不超过当前系统操作数的最大版本”，并且该版本没有删除标记。

Undo 时系统操作数减一，Redo 时系统操作数加一；刷新显示时按系统操作数重新选择每个实体的有效版本。

该方案能保留实体版本并符合课件要求，但链表关系和内存管理更复杂。若现有 QCAD 框架没有提供这套结构，建议先用方案 A 完成正确功能，再根据老师要求补充操作数结构。

## 6. 必须处理的边界情况

- 没有选中实体时，移动、旋转、镜像和删除命令应被拒绝或提示；
- 空 Undo 栈不能执行 Undo，空 Redo 栈不能执行 Redo；
- 执行新操作后必须清空 Redo 栈；
- 旋转角度为零、移动距离为零、镜像前后相同等情况不应产生无意义历史记录；
- 删除后立即 Undo，实体必须完整恢复；
- 创建后连续 Undo/Redo，不能产生重复实体；
- 多次删除、撤销、重做时不能出现悬空指针或重复释放；
- 取消命令或右键退出操作状态时，不应写入 Undo 栈；
- 橡皮筋预览只能是临时显示，不能污染模型和历史记录。

## 7. 内存释放策略

建议区分“逻辑删除”和“物理释放”：

1. 执行删除时只设置删除标记，或将实体保留在历史记录中；
2. Undo/Redo 期间始终允许恢复该实体；
3. 当历史记录被清空、命令被丢弃，且实体不再被模型或其他命令引用时，再统一释放；
4. 命令析构时释放其独占的快照；实体容器析构时释放剩余实体；
5. C++ 中明确对象所有权，避免同一个指针被多个容器重复 `delete`。

如果采用智能指针，应明确 `unique_ptr` 或 `shared_ptr` 的所有权关系；如果沿用裸指针，则至少保证每个实体只有一个负责释放它的拥有者。

## 8. 推荐的开发顺序

### 第一步：读懂现有工程

找到实体基类、直线实体、命令基类、视图刷新函数、鼠标事件入口和现有选择逻辑。先确认模型容器和坐标变换的已有实现。

### 第二步：先完成直线创建和显示

确保能创建直线、刷新窗口、保存端点，并验证世界坐标与屏幕坐标转换。

### 第三步：实现四个编辑命令

按“移动 -> 旋转 -> 镜像 -> 删除”的顺序实现。每个命令先能正常执行，再加入 Undo/Redo 状态保存。

### 第四步：加入统一历史管理器

统一处理 Undo 栈、Redo 栈、命令执行、撤销、重做和新操作清空 Redo 栈。

### 第五步：补充交互细节

加入选择状态、橡皮筋预览、右键取消、无效操作提示和操作完成后的视图刷新。

### 第六步：做回归测试并整理报告

保存操作序列、预期结果和实际结果，重点测试组合操作，而不是只测试单个按钮。

## 9. 最低验收测试清单

| 测试序列 | 预期结果 |
| --- | --- |
| 创建直线 -> Undo | 直线消失 |
| 创建直线 -> Undo -> Redo | 直线恢复且只存在一条 |
| 创建 -> 移动 -> Undo | 回到创建后的原位置 |
| 创建 -> 移动 -> Undo -> Redo | 回到移动后位置 |
| 创建 -> 旋转 -> Undo | 端点恢复到旋转前 |
| 创建 -> 镜像 -> Undo | 端点恢复到镜像前 |
| 创建 -> 删除 -> Undo | 被删除直线恢复 |
| 创建 -> 删除 -> Undo -> Redo | 直线再次删除 |
| 创建 -> 移动 -> Undo -> 新移动 | Redo 栈被清空 |
| 多条直线分别编辑 | 只影响被选中的直线 |
| 连续 Undo 到最初状态 | 不崩溃、不出现幽灵图元 |
| 连续 Redo 到最新状态 | 不重复创建、不越界 |

## 10. 最终提交建议

建议提交内容至少包括：

1. 可运行的 QCAD 工程或源码；
2. 一份简短说明文档，写清类结构、Undo/Redo 数据结构和内存释放策略；
3. 操作演示截图或录屏，覆盖创建、移动、旋转、镜像、删除、Undo、Redo；
4. 测试记录，列出关键操作序列和结果。

报告中应重点解释：为什么每个操作能撤销和重做、如何保证新操作清空 Redo、删除后的实体何时释放、以及如何避免重复释放和悬空指针。

## 11. 完成标准

完成本方案后，用户应能在 QCAD 中对直线进行五类操作，并可以任意组合这些操作，在历史范围内稳定地 Undo/Redo；界面操作能够取消，模型显示与数据状态保持一致，程序退出或清理历史时不发生内存泄漏。
