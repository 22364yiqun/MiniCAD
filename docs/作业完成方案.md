# 第一次作业要求与实现方案：直线操作

## 1. 作业要求

本次作业以直线实体为对象，参考课件和给定工程中的类设计思路，完成以下内容：

1. 参考 `Entity`、`Command` 等类的组织方式，实现直线实体及其操作命令；
2. 实现直线的五类基本操作：
   - 创建；
   - 删除；
   - 移动；
   - 旋转；
   - 镜像；
3. 为上述操作提供撤销和重做功能；
4. 正确管理实体和操作历史所占用的内存；
5. 可以采用“操作数”方法作为 Undo/Redo 的实现方式。采用该方法时，需要设计双十字链表，并维护实体操作数和系统操作数。

其中，直线五类操作是必须完成的功能；操作数、双十字链表属于可选的实现方案，但如果采用该方案，必须同时处理版本查找、撤销重做和内存释放问题。

## 2. 类设计思路

建议按“命令对象 + 实体对象”的方式组织程序：

```text
用户操作
   |
   v
具体命令（CreateLineCmd、DeleteLineCmd、MoveLineCmd、RotateLineCmd、MirrorLineCmd）
   |
   v
直线实体（LineEntity）
   |
   v
实体容器与操作历史管理器
```

直线实体至少保存：

```text
LineEntity
  id                  唯一编号
  start, end          两个端点
  deleted             删除标记或当前可见状态
  entityOperation     实体操作数（采用操作数方案时使用）
```

命令对象负责描述一次完整操作。命令执行前应保存必要的旧状态，执行后保存新状态，使 Undo/Redo 能够恢复确定的结果，而不是依赖重复计算。

## 3. 直线五类操作

### 3.1 创建

通过用户输入两个端点创建一条直线，并将创建操作记录到历史中。交互界面可以在输入第二个端点前显示橡皮筋预览，但预览不能写入正式模型或历史记录。

Undo 创建操作时应隐藏或删除该实体，Redo 时恢复同一实体，不能重复创建出多个实体。

### 3.2 删除

删除前先确定目标直线并保存其完整状态。执行删除时建议先设置删除标记，不要立即释放实体内存，以便 Undo 恢复。

Undo 应恢复原实体及其端点；Redo 应再次将其标记为删除。只有当相关历史记录被清除、实体不再可能恢复时，才能物理释放内存。

### 3.3 移动

给定平移量 `(dx, dy)`，将直线两个端点同时平移：

```text
newStart = oldStart + (dx, dy)
newEnd   = oldEnd   + (dx, dy)
```

命令需要保存移动前后的端点。Undo 恢复旧坐标，Redo 设置新坐标。鼠标移动过程中的临时预览不应产生多条历史记录，确认操作后只记录一次。

### 3.4 旋转

围绕指定中心 `C(cx, cy)` 旋转角度 `theta`。端点 `P(x, y)` 的旋转结果为：

```text
x' = cx + (x-cx)cos(theta) - (y-cy)sin(theta)
y' = cy + (x-cx)sin(theta) + (y-cy)cos(theta)
```

应保存旋转前后的两个端点。Undo 直接恢复旧坐标，Redo 直接恢复新坐标，避免反复计算带来的浮点误差。

### 3.5 镜像

镜像轴可以是水平轴、垂直轴，或由两个不同点确定的任意直线。对直线的两个端点分别执行镜像即可得到新的直线。

设镜像轴上一点为 `A`，轴方向向量为 `u`，点 `P` 在轴上的投影点为 `Q`：

```text
Q  = A + u * dot(P-A, u)
P' = 2Q - P
```

镜像轴的两个点不能重合。命令同样需要保存操作前后的端点，以支持可靠的 Undo/Redo。

## 4. Undo/Redo 实现

### 4.1 命令历史方案

可以为每个操作建立一个命令对象。每个命令保存：

```text
commandType
entityId
beforeState
afterState
```

历史管理规则如下：

```text
执行新操作：执行命令 -> 放入 Undo 栈 -> 清空 Redo 栈
Undo：      从 Undo 栈取出 -> 恢复旧状态 -> 放入 Redo 栈
Redo：      从 Redo 栈取出 -> 恢复新状态 -> 放回 Undo 栈
```

空 Undo 栈或空 Redo 栈时不能执行对应操作，也不能崩溃。

### 4.2 操作数方案（可选）

也可以按照课件中的操作数思路实现。该方案需要设计双十字链表，并维护两类操作数：

- **系统操作数**：表示当前全局历史状态，Undo 时递减，Redo 时递增；
- **实体操作数**：表示某条直线最近一次有效操作所在的历史位置。

双十字链表可以同时表达两种关系：

1. 系统链：按时间顺序连接所有操作，表示全局历史；
2. 实体链：连接同一条直线产生的不同版本，表示该实体的历史变化。

每次创建、删除、移动、旋转或镜像都可以生成一个实体版本，并记录对应的系统操作数。显示模型时，对每条直线选择“不超过当前系统操作数的最后一个有效版本”；带有删除标记的版本不显示。

该方案的核心流程是：

```text
新操作：生成版本 -> 更新实体链 -> 连接系统链 -> 系统操作数加一
Undo：  系统操作数减一 -> 按操作数重新选择各实体有效版本
Redo：  系统操作数加一 -> 按操作数重新选择各实体有效版本
```

如果采用操作数方案，必须保证创建、删除和多次编辑后不会出现重复实体、错误版本或越界访问。

## 5. 内存释放要求

内存管理应区分逻辑删除和物理释放：

1. 删除操作期间只标记实体删除，或将实体版本保留在历史结构中；
2. Undo/Redo 仍可能访问被删除实体，因此不能过早释放；
3. 当历史记录被清空，且实体不再被模型、实体链或命令引用时，才允许物理释放；
4. 每个实体必须有明确的唯一所有者，避免重复 `delete`；
5. 使用智能指针时应明确 `unique_ptr` 或 `shared_ptr` 的所有权关系；
6. 使用裸指针时应统一规定创建者和释放者，并防止悬空指针。

## 6. 必须验证的情况

- 创建直线后 Undo，直线消失；
- 创建后 Undo 再 Redo，恢复同一条直线且不重复；
- 移动、旋转、镜像后 Undo，端点恢复到操作前；
- 删除后 Undo，直线完整恢复；
- 删除后 Undo 再 Redo，直线再次删除；
- 执行 Undo 后产生新操作，Redo 历史被清空；
- 连续 Undo 到最初状态不会崩溃；
- 连续 Redo 到最新状态不会重复创建或越界；
- 历史清理和程序退出时不发生内存泄漏、重复释放或悬空指针。
