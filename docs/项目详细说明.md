# MiniCAD Qt 项目详细说明

本文按“从窗口操作追到数据变化”的顺序讲解项目。建议阅读时同时打开 `src/qt_main.cpp` 和 `src/line_model.hpp`，先理解一次操作如何流过各层，再看每个功能的具体实现。

如果不熟悉 Qt Widgets，建议先读 [Qt 界面逐段讲解](Qt界面逐段讲解.md)。它从事件循环、视图与场景、信号与槽讲起，再按 `qt_main.cpp` 的代码顺序解释每个函数。

## 1. 项目做什么

这是一个使用 C++20 和 Qt 6 Widgets 编写的二维直线编辑程序。当前支持：

- 创建、选择、移动、旋转、镜像、删除直线；
- 撤销与重做；
- 网格、坐标轴、画布平移和缩放；
- 在窗口底部输入文本命令，操作与鼠标操作共享同一画布和历史记录。

项目的编辑对象只有直线。它没有文件保存、加载、DXF 转换、框选、捕捉或其他图元。当前撤销机制是“命令对象 + 完整模型快照”，没有实现作业方案中可选的操作数与双十字链表。

## 2. 目录与构建入口

| 路径 | 作用 |
| --- | --- |
| `src/line_model.hpp` | 点、直线实体、模型、几何变换、五种命令、历史管理。无 Qt 依赖。 |
| `src/qt_main.cpp` | Qt 窗口、画布、交互、绘制、文本命令解析与程序入口。 |
| `tests/qt_history_test.cpp` | 用离屏 Qt 环境模拟鼠标与文本输入，检查主要操作。 |
| `CMakeLists.txt` | 构建 `minicad_qt` 与测试目标，链接 Qt Widgets。 |
| `CMakePresets.json` | VS Code 使用的 Debug、MinGW、Ninja 和测试预设。 |
| `docs/作业完成方案.md` | 作业要求及可选的操作数方案。 |
| `docs/实现说明.md` | 当前实现进度与限制的简要记录。 |

`main()` 位于 `src/qt_main.cpp` 末尾：创建 `QApplication`，实例化并显示 `MainWindow`，最后进入 Qt 事件循环。CMake 使用 C++20，生成 `minicad_qt`。测试文件通过定义 `MINICAD_NO_MAIN` 后包含 `qt_main.cpp`，复用其中的 `CadView` 和 `MainWindow` 定义，因此主程序入口不会在测试目标中重复出现。

## 3. 整体架构：一条直线从哪里来

可以把项目分成四层：

```text
┌──────────────────────────────────────────────────────────────┐
│ MainWindow：工具栏、镜像轴下拉框、命令面板、状态栏、Undo 按钮 │
└──────────────────────────────┬───────────────────────────────┘
                               │ 选择工具 / 输入命令
┌──────────────────────────────▼───────────────────────────────┐
│ CadView：鼠标事件、交互状态、命中检测、预览、绘制、命令解析   │
└──────────────────────────────┬───────────────────────────────┘
                               │ commit(具体 Command)
┌──────────────────────────────▼───────────────────────────────┐
│ History + Command：执行操作，保存前后状态，管理 Undo/Redo    │
└──────────────────────────────┬───────────────────────────────┘
                               │ 修改 / 恢复模型
┌──────────────────────────────▼───────────────────────────────┐
│ LineModel：以 ID 管理 LineEntity，提供基础数据操作           │
└──────────────────────────────────────────────────────────────┘
```

这些层的主要职责不同：

1. `MainWindow` 负责“把控件和用户连接起来”，不实现几何公式。
2. `CadView` 负责“解释用户正在做什么”，包括第一次点击、拖动预览和第二次点击。
3. 命令负责“描述一次确定的编辑操作”；历史管理器负责“这些操作按什么顺序撤销和重做”。
4. `LineModel` 负责“当前有哪些直线、每条直线的端点和删除状态是什么”。

鼠标和文本输入并不是两套编辑器。它们都在 `CadView` 中构造相同的具体命令，经过 `CadView::commit()` 进入同一个 `History` 和 `LineModel`。

### 3.1 一次操作的完整数据流

以输入 `move 1 20 10` 为例：

```text
QLineEdit 按 Enter
→ MainWindow 调用 view_->executeTextCommand(input)
→ 解析动词、ID、dx、dy，并检查目标是否为可见直线
→ 创建 MoveLineCommand(1, {20, 10})
→ CadView::commit()
→ History::execute()
→ StateCommand::execute() 保存 before 快照
→ MoveLineCommand::apply() 修改 LineModel 中 ID=1 的两个端点
→ StateCommand::execute() 保存 after 快照
→ History 将命令放入 Undo 栈并清空 Redo 栈
→ CadView 从模型重新提取可见直线并重画
→ MainWindow 更新 Undo/Redo 按钮
```

鼠标移动直线最后也会生成 `MoveLineCommand`。区别只在于鼠标需要在松开前提供拖动预览。

## 4. 核心数据如何抽象

### 4.1 `Point`：最小几何单位

`minicad::Point` 只有 `double x` 和 `double y`。文件中为它提供加法、减法和乘标量运算，例如平移可以直接写成 `line.start + delta`。`kPi` 用于角度换算；`kEpsilon` 用于浮点几何判断。

模型层使用自己的 `Point`，而 Qt 界面使用 `QPointF`。`CadView::toModelPoint()` 在两者之间转换。这样 `line_model.hpp` 不依赖 Qt，几何与历史逻辑可以脱离窗口理解和复用。

### 4.2 `LineEntity`：一条直线的身份与状态

`LineEntity` 包含：

```cpp
int id;
Point start;
Point end;
bool deleted;
```

`id` 是实体的稳定身份；两个端点决定几何形状；`deleted` 表示逻辑删除。界面中用于访问 `QVector<CadLine>` 的下标只表示当前显示顺序，不是稳定身份。比如删除第一条线后，其他线的下标可能变化，但它们的 `id` 不变。因此命令都以 `id` 定位目标，而不是保存界面下标。

### 4.3 `LineModel`：数据的正式存放处

模型内部用 `std::map<int, LineEntity> lines_` 保存实体，键为直线 ID。`nextId_` 从 1 开始，为新直线分配编号。

| 方法 | 作用 |
| --- | --- |
| `create(start, end)` | 用 `nextId_` 创建实体，再递增编号。 |
| `erase(id)` | 将目标实体标记为删除，不立即从 `map` 移走。 |
| `setLine(id, start, end, deleted)` | 设置已有实体的端点和删除状态。 |
| `require(id)` | 查找实体；ID 不存在时抛出异常。 |
| `visibleLines()` | 只返回 `deleted == false` 的实体，供界面显示。 |
| `snapshot()` / `restore()` | 复制或恢复直线表，供历史机制使用。 |

`require()` 分只读和可修改版本。可修改版本通过调用只读版本复用查找与报错逻辑，然后返回可修改引用。

**逻辑删除的结果**：用户看不到被删除的直线，但模型仍保留它。Undo 恢复旧状态时，原来的 ID 和端点可以准确回来。

### 4.4 `FullState`：为什么还要保存 `nextId`

`ModelState` 只是整张直线表；`FullState` 则同时保存直线表和 `nextId`。`capture(model)` 捕获这两部分，`restore(model, state)` 同时还原它们。

假设初始 `nextId = 1`，创建一条线后变为 2。Undo 创建会恢复到没有直线、`nextId = 1` 的状态；Redo 则恢复到直线 ID 为 1、`nextId = 2` 的状态。Redo 是恢复快照，不再次调用 `create()`，因此不会重复生成新编号或多出一条线。

## 5. 命令与历史如何抽象

### 5.1 `Command`：统一的操作接口

`Command` 是抽象类，定义：

```cpp
virtual const char* name() const = 0;
virtual void execute(LineModel&) = 0;
virtual void undo(LineModel&) = 0;
virtual void redo(LineModel&) = 0;
```

历史管理器只依赖这个统一接口，不必知道当前操作是移动还是镜像。这是命令模式在本项目中的核心作用：把“用户请求做的一件事”封装为对象。

### 5.2 `StateCommand`：复用撤销机制

五种具体命令都继承 `StateCommand`。它把相同的历史逻辑集中在一处：

```text
execute：捕获 before → 调用具体命令的 apply() → 捕获 after
undo：恢复 before
redo：恢复 after
```

具体命令只需实现 `apply(LineModel&)`，无需各写一遍 Undo/Redo。`before_` 和 `after_` 用 `std::optional<FullState>` 保存；未执行的命令若被要求撤销或重做，会抛出逻辑错误。

这里保存的是**整个模型的快照**，不是仅保存目标直线的旧、新端点。这简化了实现，也使创建、删除和编号恢复使用同一套规则；代价是每条历史记录都需要复制当时所有实体。

### 5.3 五种具体命令

| 类 | 构造时保存什么 | `apply()` 做什么 |
| --- | --- | --- |
| `CreateLineCommand` | 起点、终点 | 调用 `model.create()`。 |
| `DeleteLineCommand` | 目标 ID | 调用 `model.erase()`。 |
| `MoveLineCommand` | 目标 ID、位移向量 | 两端点分别加位移。 |
| `RotateLineCommand` | 目标 ID、中心、角度 | 两端点分别调用 `rotatePoint()`。 |
| `MirrorLineCommand` | 目标 ID、轴上的两点 | 两端点分别调用 `mirrorPoint()`。 |

这些类只保存完成操作所需的参数；通用的前后快照保存在它们的基类中。

### 5.4 `History`：两个栈

`History` 维护 `undo_` 与 `redo_`，元素类型是 `std::unique_ptr<Command>`。`unique_ptr` 表示每个命令在任一时刻只由一个栈拥有；命令在两个栈之间通过 `std::move` 转移，不复制命令对象。

```text
执行新命令：执行 → 压入 Undo 栈 → 清空 Redo 栈
Undo：从 Undo 栈取出 → 恢复 before → 压入 Redo 栈
Redo：从 Redo 栈取出 → 恢复 after → 压入 Undo 栈
```

如果栈为空，`undo()` 或 `redo()` 返回 `false`。执行新操作会清空 Redo 栈，是因为旧的“未来状态”已经不再沿着当前编辑分支继续。

例如：

```text
创建 A → 移动 A → Undo 移动 → 镜像 A
```

提交镜像时，原本可重做的“移动 A”被清除。此时再 Redo 不会重新移动 A。

## 6. 几何操作的数学实现

### 6.1 创建

`LineModel::create()` 分配 ID，将两个端点和 `deleted=false` 放入 `map`。没有额外的线段对象继承体系：当前只支持直线，所以 `LineEntity` 直接表示编辑实体。

### 6.2 移动

位移量为 `D=(dx, dy)` 时：

```text
start' = start + D
end'   = end   + D
```

`MoveLineCommand::apply()` 先读取目标直线，再调用 `setLine()` 写回新端点。它沿用目标原有的 `deleted` 值；界面和文本命令在提交前会限制用户只能选择可见直线。

### 6.3 旋转

`RotateLineCommand` 构造时将角度从度转换为弧度。设中心为 `C=(cx,cy)`，点为 `P=(x,y)`，令 `q=P-C`，则：

```text
x' = cx + qx cosθ - qy sinθ
y' = cy + qx sinθ + qy cosθ
```

`rotatePoint()` 对起点和终点分别应用公式。模型只需知道中心与角度，不关心角度来自鼠标拖动还是文本命令。

### 6.4 镜像

用轴上的两点 `A`、`B` 确定任意镜像轴。令 `u=B-A`，对待镜像点 `P` 求其在轴上的投影：

```text
t  = dot(P-A, u) / dot(u, u)
Q  = A + t·u
P' = 2Q - P
```

`mirrorPoint()` 先检查轴长平方，轴上两点过近时抛出 `invalid_argument`。`MirrorLineCommand` 对两个端点分别做镜像。X 轴、Y 轴与两条对角线只是界面提供的轴点预设，最终都走同一个命令和几何函数。

## 7. Qt 界面各部分如何工作

### 7.1 `MainWindow`：组装窗口

`MainWindow` 继承 `QMainWindow`，把 `CadView` 设为中央控件，然后创建：

- 互斥的工具栏动作：选择、直线、移动、旋转、镜像、删除；
- 镜像轴下拉框；
- 撤销、重做按钮和 Qt 快捷键；
- 底部 `QDockWidget` 命令面板，包含只读日志、提示文本和输入框；
- 状态栏。

工具栏的 `QActionGroup` 设置为互斥，因此一次只激活一个工具。选择工具时调用 `CadView::setTool()`，同时清除正在进行的画线或自定义镜像交互。镜像轴下拉框调用 `setMirrorAxis()`。

`CadView` 不直接操作窗口控件，而是通过三个 `std::function` 回调告知窗口：

| 回调 | 发生时机 | 窗口响应 |
| --- | --- | --- |
| `changed` | 模型或历史发生变化 | 更新 Undo/Redo 按钮状态。 |
| `command` | 产生一条操作消息 | 追加到底部日志。 |
| `liveStatus` | 鼠标移动或交互提示变化 | 更新提示标签和状态栏。 |

这是一种轻量的视图与窗口通信方式。它没有为这些通知声明自定义 Qt signal。

### 7.2 `CadView`：一份正式状态，一份显示状态

`CadView` 继承 `QGraphicsView`，包含 `LineModel model_` 和 `History history_`。它还有公开的 `QVector<CadLine> lines`，保存当前可见直线的 Qt 版本：`id`、`QPointF a`、`QPointF b`。

这两份状态的职责不同：

| 数据 | 作用 |
| --- | --- |
| `model_` | 正式数据，命令和撤销重做都作用于此。 |
| `lines` | 显示、命中检测、选择与拖动预览。 |
| `before_` | 鼠标拖动开始时的 `lines` 副本，用来计算预览及最终变化。 |

`syncFromModel()` 清空 `lines`，遍历 `model_.visibleLines()`，把模型点转换为 `QPointF` 后重建显示数组。`rebuild()` 清空 `QGraphicsScene`，重新画全部可见直线、选中端点和临时预览。因此，操作提交后的模型是显示数据的来源。

**理解预览的关键**：拖动时修改 `lines`，尚未修改 `model_`；鼠标松开后才创建并提交命令。提交后 `syncFromModel()` 又用正式模型刷新 `lines`。一次长拖动只形成一次历史操作。

### 7.3 选择与命中检测

`hitLine(p)` 遍历可见直线，求鼠标点到每条**线段**的最近距离。计算时把投影参数限制在 `[0,1]`，使最近点不能跑到线段外。选择距离最近、且在阈值内的直线。阈值约为 `10 / 当前缩放倍数` 个场景单位，因此缩放后屏幕上的点击容差大致相同。

`selected_`、`active_`、`mirrorTarget_` 等字段保存的是当前 `lines` 下标，不是直线 ID；正式命令创建时会取 `lines[index].id`。

### 7.4 绘制与背景

`rebuild()` 用 `scene()->clear()` 清除旧图元，再遍历 `lines` 画线。选中的线使用另一种颜色，并在端点画小圆形控制点。绘制预览使用虚线或轴线图元，但这些临时图元不属于模型。

`drawBackground()` 在当前可见场景区域每隔 20 个场景单位画网格，并绘制 X、Y 坐标轴。网格是背景绘制，不是可编辑直线。Qt 场景默认屏幕坐标的 Y 轴朝下；界面显示与鼠标拖动都按这套场景坐标工作。

### 7.5 画布平移与缩放

按住鼠标中键或右键时，`panning_` 变为真；移动鼠标通过水平和垂直滚动条改变视图位置。滚轮调用 `scale()`，每次按 1.15 倍放大或缩小，然后重画。平移和缩放仅影响视图，不修改 `LineModel`，也不进入撤销历史。

## 8. 鼠标工具的交互状态

`CadView::Tool` 枚举决定鼠标事件要解释成什么操作：`Select`、`Create`、`Move`、`Rotate`、`Mirror`、`Delete`。`mousePressEvent()`、`mouseMoveEvent()`、`mouseReleaseEvent()` 共同完成一个交互；理解时要把它们连起来看。

### 8.1 直线工具：两次点击

```text
第一次点击：记录 first_，进入“等待第二点”状态
鼠标移动：更新 previewSecond_，重画橡皮筋虚线和实时长度、角度
第二次点击：构造 CreateLineCommand，提交模型，退出等待状态
```

`hasFirst_` 表示是否已有第一点，`hasPreview_` 控制预览。只有第二次点击才调用 `commit()`。

### 8.2 选择与移动工具：拖动

按下时先用 `hitLine()` 找目标。若命中，保存目标下标 `active_`、整个显示数组 `before_` 和鼠标起点 `dragStart_`。拖动时计算 `delta = 当前鼠标点 - dragStart_`，用 `before_` 中的原始端点加 `delta` 得到预览位置。每次都以原始端点为基础，可避免连续鼠标事件造成位移累积误差。

松开时若显示数组相对 `before_` 确实发生变化，计算位移并提交 `MoveLineCommand`。`Select` 工具也支持直接拖动移动直线，因此“选择”和“移动”在拖动阶段共用逻辑。

### 8.3 旋转工具：拖动求角度

按下命中直线后，以两个端点的中点为旋转中心 `center_`。程序记录鼠标相对中心的初始方向 `startAngle_`。移动鼠标时，用当前方向减初始方向得到旋转角，对 `before_` 中的两个端点做预览。松开后把该角度交给 `RotateLineCommand`。

这与文本命令不同：鼠标工具的旋转中心固定为直线中点；文本命令 `rotate id cx cy degrees` 允许指定任意中心。

### 8.4 镜像工具：预设轴与自定义轴

预设轴模式下，点击目标直线就可以提交镜像。`presetAxis()` 把 X 轴、Y 轴、`y=x`、`y=-x` 各表示为两个轴点。

自定义轴模式有三个步骤：选中待镜像直线、点击轴第一点、点击轴第二点。`mirrorTarget_` 保存目标下标，`mirrorHasFirstAxis_` 表示是否已取得轴第一点；鼠标移动时会预览轴线。第二点与第一点足够分开后，才提交 `MirrorLineCommand`。切换工具或镜像轴时会重置这些中间状态。

### 8.5 删除工具

点击命中的可见直线后，按它的 ID 构造 `DeleteLineCommand` 并立即提交。`syncFromModel()` 随后只提取未删除的实体，所以这条线从画布消失。

## 9. 文本命令如何工作

底部输入框按 Enter 时，`MainWindow` 把文本传给 `CadView::executeTextCommand()`，并把输入及返回结果写入日志。

解析器先做 `simplified()`，按空格拆分，再将动词转小写。各命令检查参数数量；坐标与角度必须能解析为有限的 `double`；ID 必须是正整数。对删除、移动、旋转和镜像，还会检查 ID 对应的直线是否在当前可见列表中。异常被捕获并返回以“错误：”开头的文字。

| 命令 | 功能 |
| --- | --- |
| `create x1 y1 x2 y2` | 创建直线。 |
| `delete id` | 删除可见直线。 |
| `move id dx dy` | 平移直线。 |
| `rotate id cx cy degrees` | 绕指定中心旋转。 |
| `mirror id ax ay bx by` | 关于两个轴点确定的直线镜像。 |
| `undo` / `redo` | 撤销 / 重做。 |
| `list` | 列出当前可见直线及端点、长度、角度。 |
| `help` | 显示命令格式。 |

例如：

```text
create 0 0 100 0
move 1 20 10
rotate 1 70 10 90
mirror 1 0 0 0 1
list
undo
redo
```

`list`、`help` 只是查询，不进入历史。文本 `undo` 和 `redo` 使用与按钮相同的 `CadView` 方法。

## 10. 一个完整例子：创建、删除、撤销、重做

从空白画布开始：

1. 输入 `create 0 0 100 0`。`CreateLineCommand` 执行前快照是空模型、`nextId=1`；执行后快照包含 ID 1、`nextId=2`。
2. 输入 `delete 1`。`DeleteLineCommand` 执行前快照里 ID 1 可见；执行后快照里 ID 1 仍存在但 `deleted=true`。画布过滤它，所以看起来已删除。
3. 输入 `undo`。History 取出删除命令，恢复其前快照；ID 1 再次可见。
4. 再输入 `undo`。History 取出创建命令，恢复创建前快照；画布为空，`nextId` 也回到 1。
5. 连续输入两次 `redo`。第一次恢复创建后的快照，第二次恢复删除后的快照。整个过程不会重复生成实体。

这个例子同时说明了三件事：删除是逻辑删除；撤销重做恢复的是状态；ID 分配状态也属于被保存的模型状态。

## 11. 内存与对象所有权

- `LineModel` 的 `std::map` 直接拥有所有 `LineEntity` 值对象；没有手工 `new` 或 `delete` 直线。
- `History` 的两个 `std::vector<std::unique_ptr<Command>>` 拥有命令对象。清空 Redo 栈或销毁 History 时，命令及其快照自动释放。
- `QGraphicsScene` 和大部分控件采用 Qt 父对象机制；`scene()->clear()` 会清理场景里旧的图元。
- 删除直线只设置标记，不立即回收实体。它仍在当前模型中，直到后续状态恢复或模型整体销毁。

需要区分**逻辑删除**与**内存释放**：前者决定画布是否显示，后者由容器和对象生命周期管理。当前实现通过值对象、标准容器、智能指针和 Qt 父对象所有权避免手工释放错误。

## 12. 当前设计的优点与代价

### 12.1 优点

1. **核心逻辑与 Qt 解耦**：几何、模型、命令和历史在 `line_model.hpp` 中，不需要窗口才能理解其规则。
2. **输入方式统一**：鼠标和文本命令最终使用相同的具体命令，不会各自维护一份正式模型。
3. **撤销语义直观**：恢复前后状态，不依赖“反向旋转”“反向移动”等逆运算，减少浮点误差累积。
4. **交互预览与正式状态分离**：鼠标每移动一小步不会生成一条历史记录。
5. **所有权明确**：模型值对象、命令智能指针和 Qt 父对象分别负责资源生命周期。

### 12.2 代价和范围

1. **快照开销随模型规模增长**：每次操作都复制所有直线及 `nextId`，历史越长、实体越多，占用的时间和内存越多。
2. **绘制采用全量重建**：`rebuild()` 每次清空场景并重新添加全部可见直线，适合当前小项目，数据量大时应考虑增量更新。
3. **`CadView` 承担较多职责**：它同时处理鼠标状态、文本解析、模型同步和绘制。继续扩展更多图元时，可以把文本解析、交互工具和渲染进一步拆开。
4. **目前只有直线图元**：`LineEntity` 与五种命令都专门针对直线；加入圆、弧或多边形需要扩展模型和命令设计。
5. **没有持久化**：退出程序后画布和历史不会保存。
6. **没有操作数与双十字链表**：作业文档将其作为可选实现方案介绍，但当前代码没有这套结构。

## 14. 推荐阅读源码的顺序

1. 从 `line_model.hpp` 的 `Point`、`LineEntity`、`LineModel` 读起，确认“真实数据”是什么。
2. 接着读 `FullState`、`Command`、`StateCommand`、五个具体命令和 `History`，理解“操作如何成为可撤销对象”。
3. 看 `qt_main.cpp` 的 `CadView::commit()`、`syncFromModel()` 和 `rebuild()`，理解“模型如何变成画布”。
4. 看 `mousePressEvent()`、`mouseMoveEvent()`、`mouseReleaseEvent()`，把每个工具的按下、预览、确认连起来。
5. 看 `executeTextCommand()`，理解另一种输入方式如何汇入相同的命令管线。
6. 最后看 `MainWindow` 和测试，理解 Qt 控件的连接及用户可见的完整流程。

记住这条主线，就能定位大部分问题：**输入产生交互意图 → 交互意图变成命令 → 命令修改模型并留下历史 → 模型同步到可见直线 → 场景重画。**
